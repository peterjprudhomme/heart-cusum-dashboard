# HEART h=5 — single-file CUSUM dashboard

This package creates **one self-contained DuckDB file** from the CUSUM/FDA outputs already generated by your HEART project. The Streamlit app reads **only that one database file**. It does not read, link, or require source Parquets or FDA CSVs after the build.

## Included in the database

| Table | Data included | Why |
|---|---|---|
| `pairs` | Only active ingredient–reaction pairs with a **first CUSUM alarm at h=5** (expected 616,086) | Search and pair details |
| `quarterly_scores` | Every available monitoring-quarter CUSUM score **for those alarmed pairs only** | Per-pair score timelines, pair counts, reporting proportions |
| `fda_listings` | **All 459 original FDA archived listings**, including those outside the 2021Q1–2026Q2 monitoring window | Show all FDA safety-concern listings; filter to the 351 monitoring listings for evaluation |
| `fda_links` | All amended FDA ingredient–reaction mappings to original listing IDs, including nonmatches | Display mapped pairs, original product, FDA source and before/same/after timing |
| `fda_reference_pairs` | The amended FDA reference labels for the monitoring window (expected 1,001) | Retain 255 matched and 746 unmatched reference pairs in the *FDA reference* without adding nonalarmed pairs to the CUSUM pair catalog |
| `alarms_by_quarter` | First alarm counts for each 2021Q1–2026Q2 quarter | Overall first-alarm chart; should sum to 616,086 |
| `kpis` | Dataset-level denominators, alarm rate, FDA coverage, median signed listing lead | Accurate rates without storing millions of nonalarming CUSUM pairs |
| `metadata` | Provenance, mapping limitations, missing FDA archive quarters | Proper interpretation |

**Definition:** A pair is `(prod_ai active ingredient, MedDRA reaction)`; not a reported drug name. “h=5 alarm” is the **first** quarter where the previously computed CUSUM crossed the threshold under the same minimum-case rule.

## 1. Install

From your `CUSUM_exp` project directory:

```powershell
pip install duckdb pandas plotly streamlit
```

## 2. Extract package

Unzip the download at the project root so the files live here:

## 3. Build the one-file dataset (run once)

```powershell
python HEART_h5_dashboard_package/build_h5_dashboard_db.py --output data/heart_dashboard_h5.duckdb --memory-limit 8GB
```

If rebuilding an existing database:

```powershell
python HEART_h5_dashboard_package/build_h5_dashboard_db.py --output data/heart_dashboard_h5.duckdb --memory-limit 8GB --overwrite
```

The exporter reads the original ~3.38-million-row summary and ~69-million-row quarterly Parquet, **filters to h=5 alarmed pairs**, and embeds only their histories. It may consume substantial CPU, disk space and scratch space during export. The resulting database size depends on how many monitoring quarters those alarmed pairs span. Monitor available disk space. No original Parquet/CSV file paths are stored as runtime dependencies.

When `fda_final_summary.json` is present, the exporter validates its summary counts against the new database, rather than silently combining mismatched results from different runs.

## 4. Run the dashboard (one input file)

```powershell
streamlit run HEART_h5_dashboard_package/heart_h5_dashboard.py
```

The dashboard opens `data/heart_dashboard_h5.duckdb` by default. If the database has been moved, set its path in the Streamlit sidebar or set `HEART_H5_DB` in the environment.

The Streamlit app needs **only the `.duckdb` file**, so to move the dashboard to another computer, copy that database and the `heart_h5_dashboard.py` script, install the Python dependencies, and run the same Streamlit command. The build sources are not needed in the deployment folder.

## 5. Sanity-check the output

In a Python shell:

```python
import duckdb
with duckdb.connect('data/heart_dashboard_h5.duckdb', read_only=True) as c:
    print(c.sql('SELECT * FROM kpis').df().T)
    print(c.sql('SELECT COUNT(*) FROM pairs').fetchone())
    print(c.sql('SELECT COUNT(*) FROM fda_listings').fetchone())
    print(c.sql('SELECT SUM(first_alarms) FROM alarms_by_quarter').fetchone())
    print(c.sql('SELECT COUNT(*) FROM quarterly_scores').fetchone())
```

Expected based on your latest runs:

- `pairs`: **616,086** h=5 alarmed pairs
- `kpis.total_cusum_scored_pairs`: **3,378,364** (aggregate only)
- `kpis.overall_alarm_rate_h5`: **~0.18236**
- `fda_listings`: **459** original FDA listings total, of which **351** are in the monitoring window
- `fda_reference_pairs`: **1,001** amended FDA reference pairs (in-window first listings)
- `kpis.matched_reference_pairs`: **255**
- `kpis.matched_listings`: **130** (out of 279 mapped original monitoring listings)
- `kpis.median_listing_signed_lead_quarters`: **+2.0**
- `SUM(alarms_by_quarter.first_alarms)`: **616,086**

If those numbers don't agree, the builder either rejects the mismatched FDA results (if final summary is present) or you should investigate whether the source files came from different CUSUM runs.

## Dashboard sections

1. **Search alarmed pairs:** ingredient/reaction search (both optional but at least one is needed), sortable pair results, CUSUM score versus h=5 by quarter, quarterly co-report counts, FDA links and signed lead time.
2. **FDA comparisons:** reference-pair matched/unmatched counts, listing-level matched/missing outcomes, before/same/after timing, full FDA listing search and optional CSV exports.
3. **Overall alarms:** first alarms by quarter and quarterly count table.

## Important evaluation boundaries

- The **18.24%** rate uses **all scored pairs** as denominator, even though only h=5 alarmed pairs are in the dashboard pair table. Computing the rate from the dashboard `pairs` table alone would incorrectly give 100%.
- FDA pair and FDA listing denominators remain intact. Nonalarmed FDA *reference labels* are retained to show nondetection, but no nonalarmed CUSUM pairs are included in the searchable catalog.
- Lead time is `FDA first-listed quarter in the supplied archive - CUSUM first-alarm quarter` and can be positive (CUSUM earlier) or negative (CUSUM later). Median is calculated over **matched original FDA listings** only; this is not median lead time over every listed concern.
- The FDA archive lacks 2021Q2–2022Q1 pages and FDA mappings include project-approved ingredient corrections alongside provisional source mappings. This is exploratory comparison, **not clinical validation**.
- Retrospective selection of the CUSUM pair universe and possible omission of zero-count reaction quarters are unresolved analytical limitations inherited from the scored data. The exporter does **not** modify CUSUM scores or create unobserved quarters.
- The overall 616,086 alarms are exploratory FAERS co-reporting signals, not confirmed adverse reactions or verified false positives.
